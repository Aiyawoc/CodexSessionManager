# ADR 0011：版本无关、契约敏感的 App Server 操作边界

- 状态：已接受
- 日期：2026-09-01
- 范围：任务盘点、完整备份、批量归档和反归档

## 背景

CSM 过去以 `codex_version + 全量 schema_sha256` 精确命中人工画像作为通用写入门禁。全量 schema 同时包含稳定接口、实验接口和与任务管理无关的定义，因此 Codex Desktop 的模型、插件或其它无关变化也会关闭归档能力，并迫使 CSM 跟随每次桌面端发布。

这把两个不同问题混成了一个判断：运行时证据是否发生变化，以及 CSM 实际依赖的操作语义是否仍然成立。前者适合诊断、审计和计划失效；后者才决定某一项操作能否继续。

## 决策

CSM 采用版本无关、契约敏感的操作评估。契约由代码库中的静态规则定义，并由维护者人工审查；运行时只检查实际 App Server 是否满足已批准的最小契约，不自动学习或扩大写入语义。

**当前 Codex 版本、二进制散列和全量 schema 散列是诊断与计划失效证据，不是归档授权条件。**它们仍保存在能力报告、审计和不可变计划中；任一值在计划生成后变化都会使计划失效并要求重新规划，但单独变化不会授权或拒绝归档。

**归档与反归档由静态、人工复核的最小操作契约逐项评估。**能力矩阵不再使用单一的全局写入布尔值。

**无关变化自动兼容；相关方法/字段/关键枚举不兼容时只关闭受影响操作。**读取、备份和其它仍兼容的操作继续可用，并向用户报告具体方法、字段或枚举原因。

App Server 仍是 Codex 任务在线读取和写入的唯一边界；CSM 不直接修改 rollout JSONL、SQLite、认证文件或 Codex 配置。

## 最小操作契约

当前固定五项契约，每项都有稳定的 `contract_id`、规则版本、规则指纹、运行时契约指纹、必需方法/字段、兼容变化、失败变化以及写前和写后可观测条件：

| 契约 | 必需能力 | 通过条件 |
| --- | --- | --- |
| `inventory.common.v1` | `initialize`、`thread/list`、`thread/read`、`thread/loaded/list` | 任务 ID、归档状态、运行状态、父子关系、临时状态和历史模式可确定 |
| `history.legacy.v1` | `thread/read` | turns/items 可完整建立内容指纹和逻辑备份 |
| `history.paginated.v1` | `thread/turns/list` | `itemsView=full`、升序分页、cursor 可证明终止且 items 完整 |
| `archive.v1` | `thread/archive`、归档通知、归档后列表/读取 | 单根请求成功后，完整后代闭包逐项重读为已归档 |
| `unarchive.v1` | 已归档列表/读取、`thread/unarchive`、恢复通知 | 单根请求成功后，目标闭包逐项重读为活跃 |

`history.paginated.v1` 的实验方法依赖只影响分页历史任务；普通历史任务仍可使用 `history.legacy.v1`。GUI、CLI、Skill 和领域工作流必须调用同一逐操作能力查询边界。

## 兼容与失败规则

以下变化自动兼容：Codex 版本、二进制哈希或全量 schema 哈希变化；新增无关方法/定义；无关方法在稳定与实验集合间迁移；描述、标题、默认值、定义顺序或 JSON 键顺序变化；契约对象新增不改变已用类型、必需性或已知枚举语义的可选字段。

以下变化只关闭受影响操作：必需方法删除、改名或稳定性降低；CSM 请求字段删除、改名、类型不兼容或新增无法满足的必填字段；CSM 使用的响应字段删除、类型不兼容或必需性改变；出现未知关键状态、历史模式或关系枚举；分页失去完整 items 或可证明终止；归档/反归档响应与写后状态无法一致映射；schema 生成、解析或契约投影失败。

未知字段不会被自动加入信任规则，未知关键值只阻塞包含该任务的选择。无关变化不要求 CSM 跟随发布；相关破坏必须给出结构化原因，并在必要时发布新的契约规则版本。

## 写入、安全与计划不变量

- 当前对 Codex 任务的唯一在线写入是 `thread/archive` 和 `thread/unarchive`；两者都必须经过不可变计划、人工确认、已复验备份、完整后代闭包、状态/内容/能力指纹和写后重读。
- 归档/反归档只针对用户明确选择的根及完整后代闭包；混合归档状态、固定/活动/加载中、映射或内容不完整、未知状态、账号根冲突均停止受影响写入。
- 计划绑定契约规则指纹、运行时契约指纹、全量 schema 哈希、目标状态与内容指纹、账号根、闭包和有效期。任何漂移都使计划失效，不修补旧计划、不盲目重试。
- 写入超时或断线先逐项重读并 reconcile；响应丢失和部分闭包结果不得报告为已完成。
- 永久删除、重命名、restore/import 写入、原任务或派生上下文应用不属于当前 Codex 写能力；MCP、Skill、Hook 和普通 CLI/HTTP profile 不提供绕过上述边界的写入器。
- 本地 CSM 计划、备份、记忆文件和审计仍按各自计划与原子写入不变量处理；本 ADR 不把这些本地文件写入变成 Codex App Server 能力。

## 迁移

保留 `codex_version`、二进制 SHA-256、全量 schema SHA-256、稳定/实验方法和初始化响应指纹，用于诊断、审计和计划失效。现有精确版本画像作为历史兼容语料和回归证据保留，但不再作为归档/反归档授权白名单。

`SchemaAuditReport` 与能力矩阵改为封存五项 `operation_capabilities`，每项输出 `available`、契约 ID、规则/运行时指纹和结构化阻塞原因。历史精确画像与真实账号验收正文不重写；只在顶部标记其局部被本 ADR 取代，并链接到本记录。

第一版对外任务写能力仅包括批量归档和反归档。永久删除、rename、restore/import 写入、上下文 apply 和 MCP 写入继续不可用；缺少相关契约只关闭对应操作，不扩大为全局只读。

## 后果

Codex Desktop 的常规更新、二进制更新和无关 schema 变化不再要求 CSM 跟随发布，维护触发点缩小为 CSM 实际使用的契约语义变化。代价是规则投影必须精确维护，真正的上游破坏性变化仍会关闭对应操作；这正是为了拒绝猜测性写入。

本 ADR 局部取代 [`ADR 0001`](0001-app-server-write-boundary.md) 中“精确版本与全量 schema 哈希授权”的部分；ADR 0001 关于 App Server 唯一在线写入边界和禁止直接修改 Codex 内部文件的部分继续有效。

## 验收

至少验证：版本/二进制/全量 schema 变化和无关方法变化不关闭兼容归档；删除归档方法只关闭 `archive`；分页方法不兼容只阻塞分页历史；未知关键值只阻塞受影响任务；计划或契约指纹漂移要求重新规划；GUI、CLI 和 Skill 得出相同资格与原因；MCP 工具面没有归档/反归档执行器。真实账号归档和反归档仍必须在独立人工 Runbook 中用写后重读证据验收。
