# ADR 0010：取消固定归档等待期，保留人工永久删除证据门禁

> **SUPERSEDED（2026-09-01）**：CodexSessionManager 第一版已取消永久删除能力。本文件仅保留历史决策与失败证据，不描述当前产品功能，也不授权任何删除操作。

- 状态：Superseded
- 日期：2026-09-01
- 关联：ADR 0001、ADR 0002、v1.1 本机受控验收 2.5

> 实施状态补充（2026-09-01）：下文关于 GUI/CLI 删除应用可执行和同轮闭环的表述已 **SUPERSEDED**。真实 `thread/delete` 发生部分提交后，2.5 已按 [`CLOSED_WITH_UPSTREAM_BLOCKER`](v1.1.0-phase-2.5-permanent-purge-closure.md) 关闭应用；随后第一版完全移除了该能力。

## 背景

原策略要求 CSM 可信归档记录至少经过 14 天后才能生成永久删除计划。该时间条件会让受控真实验收无法在同一轮闭环，但时间经过本身不能证明备份仍有效、归档确由 CSM 完成或目标仍安全。

完整备份也不能单独作为删除授权：它可能尚未与一次成功归档及其后置状态绑定。

## 决策

1. 永久删除不再要求固定归档等待天数；
2. 目标必须先由 CSM 成功归档，并具有 CSM 审计链中的可信归档证据；
3. 可信归档证据记录的 backup manifest 必须与目标当前指纹对应的有效加密备份完全一致；只有完整备份而没有可信归档证据时拒绝删除；
4. GUI 删除入口只对用户单选的一个已归档、inactive、非 pinned、非 ephemeral 根开放；完整后代闭包在计划和执行前重新读取；
5. 永久删除继续使用独立不可变单根计划、能力/状态/内容/闭包漂移复核、loaded 与后台终端检查、其它 Codex 进程检查和单次精确确认短语“确认删除”；此前要求用户抄写 plan ID 后再输入英文短语的双重输入细节标记为 **SUPERSEDED（2026-09-01）**，计划 ID 仍只读展示并由执行器复核计划 SHA-256；
6. 自动清理、Hook 和 MCP 不获得永久删除执行能力；CLI 保留显式的人工计划与应用流程；
7. 真实账号永久删除验收默认禁止。只有用户明确要求、全数据根回滚快照已完整复验、目标由用户在 GUI 精确单选且全部门禁通过时，才允许一次受控例外。

## 结果

- 新完成的可信归档可以立即进入人工删除计划，2.5 可在同一轮受控验收闭环；
- 删除资格仍来自“成功归档 + archive-bound 当前备份 + 当前状态”，而不是单独备份或时间经过；
- 旧版包含 `minimum_archive_days`、但没有 `trusted_archive_required` 的 purge 计划不能在新执行器中通过；
- 归档撤销会继续先使可信归档证据失效。

本 ADR 取代现行文档中“至少 14 天”或“固定等待期”的规则。历史归档文档保持原文，不作为当前执行规则。
